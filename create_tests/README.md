# Папка `create_tests`

В этой папке находятся шаблоны промтов (prompt templates) и примеры выходных файлов,
которые используются для автоматической генерации и ревью тестовой документации с
помощью LLM.

## Содержимое папки

| Файл | Назначение |
|------|------------|
| `prompt_component.md` | Шаблон промта для генерации **компонентных** тест-кейсов (`testCaseType = component`). Содержит подробные правила формирования итогового JSON (схема `TestCase`), описание формата путей, требований к полям и ограничения по синтаксису. В шаблон вставляются: бизнес-требования (`{{REQ_CONTENT}}`), Swagger-спецификация (`{{SWAGGER_CONTENT}}` / `{{SWAGGER_URL}}`) и список UI-тестов из Figma (`{{TESTS_FROM_FIGMA_CONTENT}}`). |
| `prompt_scenario.md` | Шаблон промта для генерации **сценарных** (end-to-end) тестов (`testCaseType = scenario`). Отличается от предыдущего правилами именования, лейблов и приоритетов. В шаблон так же внедряются бизнес-требования, Swagger и сгенерированные компонентные тесты для контекста. |
| `review_component.md` | Чек-лист/гайдлайн для ручного ревью сгенерированных компонентных тестов. Позволяет проверить соответствие формату JSON, полноте покрытия и логике шагов. |
| `component_tests.json` | Пример (reference) выходного файла, сгенерированного по шаблону `prompt_component.md`. Содержит демонстрационный набор компонентных тест-кейсов. |
| `scenario_tests.json` | Пример выходного файла для сценарных тестов, сгенерированных по `prompt_scenario.md`. |
| `json_scheme.yml` | YAML-схема (`JSON Schema v7`) объекта `TestCase`, которая используется внутри промтов через плэйсхолдер `{{JSON_SCHEME_CONTENT}}` для валидации формата выходного JSON. |

## Как пользоваться

1. Заполни placeholders в выбранном промте реальными данными:
   * `{{REQ_CONTENT}}` — текстовый файл с бизнес-требованиями.
   * `{{SWAGGER_URL}}` и `{{SWAGGER_CONTENT}}` — ссылка на swagger и его YAML-файл.
   * `{{TESTS_FROM_FIGMA_CONTENT}}` — csv-файл с краткими тестами на дизайн (только для `prompt_component.md`).
   * `{{JSON_SCHEME_CONTENT}}` — YAML-схема `TestCase` из файла `json_scheme.yml`, необходима для валидации формата итогового JSON. Обычно подставляется автоматически скриптом, при ручном использовании — вставь содержимое файла самостоятельно.
   * `{{COMPONENT_TESTS_CONTENT}}` — json с компонентными тестами (только для `prompt_scenario.md`).
2. Передай заполненный текст LLM (ChatGPT, Claude и т.д.).
3. Полученный JSON-массив сохранить в репозиторий или импортировать в тест-менеджмент-систему.
4. Используй `review_component.md` как чек-лист для быстрой проверки качества результата.

## Полезно знать

* Все шаблоны написаны на русском языке и строго регламентируют формат выходных данных.
* Запрещено использовать обратные кавычки (\`) для monospace-форматирования — вместо этого применяется конструкция `{{text}}`.
* Поля `testRepositoryPath`, `summary`, `labels` и другие имеют детальные ограничения, описанные внутри каждого промта —
  соблюдение их критично для корректного импорта в Jira. 
* Шаблоны остаются работоспособными даже при отсутствии отдельных источников данных. Если у вас нет Swagger-спецификации — опустите плэйсхолдеры `{{SWAGGER_URL}}` / `{{SWAGGER_CONTENT}}`; при отсутствии макетов Figma оставьте пустым `{{TESTS_FROM_FIGMA_CONTENT}}`. Для сценарных тестов допустимо не передавать компонентные тесты и т.д.
